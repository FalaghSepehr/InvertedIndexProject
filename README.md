# Inverted Index Search Engine

A full-text search engine built with **C# and .NET**, featuring both a console interface and a REST API. The search engine uses an **inverted index** data structure for efficient text document retrieval.

## Features

- Inverted index for efficient full-text search
- Text processing pipeline including:
  - Tokenization
  - Symbol and number removal
  - Stop-word filtering
  - Porter stemming
- Raw and processed token storage for different search requirements
- Bigram generation for two-word exact phrase matching
- Query parser supporting:
  - `+` — at least one matching term
  - `-` — must not contain the term
  - Bare words — must contain the term
  - `"..."` — exact phrase matching (up to two words)
- Interactive console search interface
- REST API built with ASP.NET Core
- Dependency Injection using `Microsoft.Extensions.DependencyInjection`
- Configuration through `appsettings.json`
- Unit and integration testing with xUnit and NSubstitute
- CI/CD with GitHub Actions
- NuGet package publishing
- Code coverage tracked with Codecov

## How It Works

1. Documents are loaded from the Documents/ directory.
2. Each document goes through the text-processing pipeline.
3. Text is tokenized, symbols and numbers are removed, stop words are filtered, and tokens are stemmed.
4. Raw tokens, processed tokens, and bigrams are stored in the inverted index.
5. The user submits a query through the console or REST API.
6. The query parser identifies operators and exact phrases, while normal search terms are processed and stemmed.
7. The searcher performs set operations such as intersection, union, and exclusion against the inverted index.
8. Results are displayed in the console or returned as JSON through the REST API.

## REST API

The project includes a separate ASP.NET Core Web API project.

The API provides an HTTP interface to the search engine, accepting search queries and returning the corresponding search results as JSON.

### Endpoint:

```text
GET /api/search?query=your+search+terms
```
### Example request:

```text
GET /api/search?query=charging +disease -cough "star academy"
```
### Example response:

```json
["doc1", "doc3"]
```
The API does not use a database. It operates directly on the inverted index generated by the application.

## Setup

Clone the repository and restore the dependencies:

```bash
git clone <repository-url>
cd InvertedIndexProject
dotnet restore
```
Place text documents in the Documents/ directory.

Run the application:

```bash
dotnet run --project src/InvertedIndex.Console
```
Run the REST API:

```bash
dotnet run --project src/InvertedIndex.Api
```

## Configuration

Application paths and other settings can be configured through:

- `src/InvertedIndex.Console/appsettings.json`
- `src/InvertedIndex.Api/appsettings.json`

This includes paths for:

- Documents
- Generated output
- Symbols
- Stop words


## Limitations
- Exact phrase matching is limited to two-word phrases through bigrams.
- Stop words and symbols are configured through files rather than through the API.
